# Pipeline за откриване и обработка на учебно съдържание — първа версия

**Състояние към 13.10.2026:** работеща първа версия с **един** реален източник (Уикипедия на български).
Учебната база **не е** попълнена от pipeline-а — това е инструментът, с който тя може да се попълва постепенно,
тема по тема, винаги с редакторска проверка.

## 1. Какво прави

```
тема от учебната програма (или свободно търсене)
  → откриване на източник (официален API)          → „Открит източник“
  → извличане на текста, версия, дата, лиценз       → „Извлечено съдържание“
  → класификация (ниво, клас, предмет, тема, език)   → или „Некласифициран материал“
  → урок-чернова: Claude (структуриран изход с цитати) или ръчно писане
  → автоматични проверки                             → „Автоматично проверено — чака редактор“ / „Проверките откриха проблеми“
  → редакторска проверка                             → „Проверено и публикувано“ / „Отхвърлено“
```

Нищо от pipeline-а не е видимо за учащите преди одобрение от редактор: уроците се създават със статус `DRAFT`
(невидим при всяка стойност на `SHOW_UNVERIFIED_CONTENT`).

Проверено от сървъра на 13.10.2026 г. (HTTP заявки с описателен User-Agent).

| Източник | Достъп | Лиценз / права | Използване |

Правила на доставчика за Уикипедия (Wikimedia API rate limits, API:Etiquette, User-Agent policy):
User-Agent с име, версия и контакт (`PIPELINE_CONTACT_EMAIL`); заявките са **последователни** (по една към домейн,
минимален интервал `PIPELINE_MIN_INTERVAL_MS`); `maxlag=5`; при `429`/`503` се спазва `Retry-After` (без него — поне 5 s
с нарастване); при `maxlag` — пауза поне 5 s. Без CAPTCHA, без заобикаляне на ограничения, без HTML scraping.

## 3. Данни

Нови модели (миграция `20261013180203_content_pipeline`), които допълват съществуващите `Source`, `Lesson`, `LessonSource`:

| Модел | Предназначение |
|---|---|
| `PipelineItem` | една задача: тема/търсене, език, етап, грешка, кандидати от търсенето, генериран резултат с цитати, разход за AI, редактор |
| `SourceDocument` | снимка на документ: доставчик, външен id, **версия и дата при източника**, постоянен URL, език (по източника и по текста), **лиценз, авторство, основание за достъп**, HTTP статус, дата на извличане, SHA-256 на текста, текст |
| `SourceChunk` | откъси от текста (~1200 знака) — единица за цитиране и проверка |
| `PipelineItemDocument` | кои документи са използвани за задачата и с какъв ранг |
| `PipelineJob` | опашка: вид стъпка, статус, опити, `runAfter`, заключване, последна грешка |
| `PipelineEvent` | история (INFO/WARN/ERROR) |
| `PipelineCheck` | резултати от автоматичните проверки |

Допълнени полета: `Source.license`, `Source.licenseUrl`, `Lesson.language`.

Дубликати на източници: една и съща версия (същият SHA-256) не се записва втори път — използва се повторно.
`Source` се обновява (дата на проверка, HTTP статус, лиценз), а не се дублира.

## 4. Опашка и worker

- PostgreSQL опашка (`FOR UPDATE SKIP LOCKED`) — без външна услуга; няколко worker-а не вземат една и съща задача.
- Временни грешки (мрежа, 5xx, 429, `maxlag`, грешки на Claude API 429/5xx) → нов опит с нарастващо изчакване
  (`PIPELINE_BACKOFF_BASE_MS`, до 4 опита). Окончателни (няма резултати, твърде кратък текст, 400 от Claude) → „Неуспешна обработка“.
  Липсваща настройка (няма ключ, невалиден ключ, изчерпан бюджет) → „Чака настройка“ без автоматични повторения.
- Прекъснат worker: задачите, заключени повече от 15 минути, се връщат в опашката.
- Повторна обработка („Обработи отново“) продължава от стъпката, която не е успяла.

Стартиране:

```bash
npm run pipeline -- enqueue --topic "Княз Борис I и покръстването"      # тема от програмата
npm run pipeline -- enqueue --topic "Строеж на атома" --curriculum fizika-10
npm run pipeline -- enqueue --query "Фотосинтеза"                       # без тема — класифицира се
npm run pipeline -- work            # постоянен worker (Ctrl+C спира след текущата задача)
npm run pipeline -- work --once     # до празна опашка
npm run pipeline -- retry <id>      # напр. след добавяне на ANTHROPIC_API_KEY
npm run pipeline -- status
```

Без постоянен процес: планировчик към `POST /api/cron/pipeline` с `Authorization: Bearer $CRON_SECRET`
(до 10 задачи / 45 s на извикване) или бутонът **„Обработи опашката сега“** в админ панела.

## 5. Генериране на урок

- **Claude** (`claude-opus-5-5`, `fallbacks: "default"`, стрийминг, структуриран изход със Zod схема): моделът получава
  само извлечените откъси с идентификатори (`S1-4` = източник 1, откъс 4) и трябва да пише със свои думи,
  да не добавя факти извън откъсите (липсите описва в `gaps`), да цитира дословно откъса за всеки ключов факт
  и да отбелязва противоречия между източниците (`conflicts`). Резултатът става урок в стандартния Markdown формат
  (въведение, обяснение, важно за запомняне, примери, чести грешки, обобщение, записки, определения, въпроси от учителя, тест)
  и се записва през същия механизъм като ръчните уроци (версии, флашкарти, тестове).
- **Ръчно писане** („Напиши урока ръчно“): чернова по шаблона, свързана с източниците — редакторът я попълва в редактора на уроци.
- Разходът се записва в `AIUsageRecord` (`purpose = pipeline-lesson`) и в задачата; месечният бюджет (`AI_MONTHLY_BUDGET_USD`) важи и тук.

## 6. Автоматични проверки

| Проверка | FAIL | WARN |
|---|---|---|
| Пълнота | липсва резюме, обяснение < 800 знака, < 3 определения, примери, обобщение, < 2 въпроса от учителя, < 3 тестови въпроса, въпрос без точно един верен отговор | |
| Шаблонен текст | неподменен шаблон | |
| Език | текстът не е на езика на задачата | |
| Цитати | цитат, който го няма в извлечения текст; < 80% от фактите с цитат | цитат от друг откъс; ръчен урок (няма цитати) |
| Числа и години | | число/година, което го няма в източниците |
| Противоречия | | отбелязани от модела; понятие с две определения; година, която източниците свързват с друго събитие (напр. „бунтът на боилите — 864 г.“ при 866 г. в източника) |
| Дубликати | | темата вече има урок; сходно заглавие в предмета (pg_trgm); източникът е използван за друга задача; повторени въпроси/понятия |
| Дословно копиране | > 25% от текста съвпада дословно (8-грами) | откъс ≥ 25 думи |
| Лиценз и авторство | липсва лиценз, авторство или основание за достъп | |
| Връзка с източниците | урокът е загубил връзката с основния източник | загубена връзка с допълнителен източник |

Проверките работят върху **текущото** съдържание на урока (и след редакция) и се пускат отново при одобрение.
Урок с FAIL не може да се одобри — нито от pipeline-а, нито чрез смяна на статуса в редактора на уроци.
Проверките са евристики: те **не заменят** редактора, а насочват вниманието му.

## 7. Админ панел

**Админ → Pipeline** (роля „редактор“): настройки и предупреждения; броячи по етап; добавяне на тема (търсене в програмите),
свободно търсене, всички теми без урок от програма; списък със задачи.
Страница на задача: източници (версия, дата, HTTP статус, лиценз, авторство, основание за достъп, SHA-256, откъси),
резултати от търсенето с оценка и причина за пропускане, урок, проверки, цитати (намерен / ненамерен), история, задачи в опашката,
действия (обработи отново, потърси източници отново, избери тема, напиши ръчно, провери отново, одобри, отхвърли).
Всички действия се записват в одит лога.

## 8. Какво трябва да се настрои

| Настройка | За какво | Без нея |
|---|---|---|
| `ANTHROPIC_API_KEY` | генериране на уроци с Claude | задачите стигат до „Чака настройка“; уроците могат да се пишат ръчно |
| `PIPELINE_CONTACT_EMAIL` | контакт в User-Agent (изискване на Wikimedia) | използва се само адресът на сайта/хранилището |
| `APP_URL` | адрес в User-Agent | адресът на хранилището |
| `CRON_SECRET` + планировчик **или** постоянен `npm run pipeline -- work` | автоматична обработка | обработка само с бутона в админ панела |
| `AI_MONTHLY_BUDGET_USD` | горна граница на разхода | 50 USD |

Незадължителни: `PIPELINE_SOURCES_PER_ITEM` (2), `PIPELINE_MIN_TEXT_CHARS` (1500), `PIPELINE_MIN_ARTICLE_BYTES` (6000),
`PIPELINE_MAX_PROMPT_CHARS` (60000), `PIPELINE_MIN_INTERVAL_MS` (1000), `PIPELINE_MAX_INLINE_WAIT_MS` (15000),
`PIPELINE_BACKOFF_BASE_MS` (30000), `PIPELINE_CLASSIFY_MIN_SCORE` (0.4), `WIKIPEDIA_BG_API_URL` (за тестове).

## 9. Тестове

- `tests/unit/pipeline.test.ts` — раздели и откъси на реална статия, език, цитати, числа, дословно копиране, противоречия по години
  върху реалните статии, подбор на кандидати от реалния резултат при търсене, лиценз, Retry-After, формат на урока.
- `tests/integration/pipeline.test.ts` — целият процес срещу базата с **реални записани отговори на Уикипедия** (локален сървър)
  и истинския Anthropic SDK срещу сървър по протокола на Messages API: без ключ → чака настройка; 401 → чака настройка;
  повторна обработка → урок → проверки → одобрение → публикуван; измислен цитат → FAIL и отказано одобрение (и през редактора);
  ново генериране → нова версия; 500 → нов опит; 429 с Retry-After → изчакване; `maxlag` → пауза ≥ 5 s; няма резултати → неуспешна;
  некласифициран → ръчен избор на тема; ръчна чернова → шаблонът не минава; 400 от Claude → неуспешна без повторения;
  прекъснат worker → задачата се връща в опашката; без дубликати на документи.
- `tests/e2e/pipeline.spec.ts` — през браузъра: тема → обработка → източници с версия и лиценз → „Чака настройка“ →
  ръчна чернова → проверките спират шаблона; ученик няма достъп.

Текстът на урока в отговора на тестовия Claude сървър е написан за теста (с дословни цитати от записаните статии) — тестовете
проверяват обработката, не качеството на модела. Качеството на реално генерираните уроци трябва да се оцени с истински ключ.

## 10. Ограничения на първата версия

- Един доставчик (Уикипедия на български). Енциклопедичният текст не е учебна програма: урокът може да не съвпада
  точно с обхвата на темата в конкретния клас — затова е задължителна редакторската проверка.
- Подборът на статии и класификацията са евристики по заглавия (напр. за „Атмосфера — време и климат“ е избрана и
  „Климатична класификация на Алисов“) — редакторът вижда всички кандидати и може да пусне ново търсене.
- AI генерирането е проверено само с протоколен тест; реален урок от Claude не е генериран (няма ключ на сървъра).
- Няма автоматично следене за нови версии на източниците („Остаряло“) — „Потърси източници отново“ е ръчно.
- Няма многоезичност извън български (схемата пази езика; доставчици за други езици не са добавени).
- Скоростта е ограничена от правилата на Wikimedia (последователни заявки) — подходящо за десетки/стотици теми на ден.
